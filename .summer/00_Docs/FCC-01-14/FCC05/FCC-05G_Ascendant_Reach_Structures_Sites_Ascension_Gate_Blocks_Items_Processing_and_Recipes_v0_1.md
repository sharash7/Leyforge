# 1. Purpose

FCC-05G is the Ascendant Reach's **physical-content integration document**.

It translates the realm identity, environments, materials, flora, creatures and civilisations established in FCC-05A–F into:

- buildable structures;
- physical sites;
- placeable Blocks;
- portable Items;
- harvested materials;
- installed components;
- processing pathways;
- recipe families;
- portal construction;
- settlement projects;
- player/Forge blueprint content.

It owns realm-local canon for:

- the twelve exact canonical signature structures;
- supporting civic, industrial, agricultural, route, rescue, High-Aether and sacred-law structure families;
- the Ascension Gate's realm-specific physical contract;
- portal upgrade pathways using Ascendant materials after first access;
- structure-function boundaries;
- realm-specific Block families and sensible shape eligibility;
- true portable Item families;
- installed components;
- material transformations;
- botanical processing;
- creature-product interfaces;
- food-processing families;
- processing-station reuse;
- construction/project handoff;
- legacy Aetheric/Divine structure reconciliation;
- legacy generic portal migration;
- Block Inventory Projection compliance.

FCC-05G does **not** own:

- universal Block runtime rules;
- universal Item runtime rules;
- universal crafting transaction mechanics;
- universal building placement physics;
- universal vessel physics;
- economy pricing;
- settlement simulation;
- dungeon/boss definitions;
- detailed sacred-law/corruption state propagation;
- final numerical recipe quantities;
- final portal progression order;
- final cross-realm recipe deduplication;
- final Block/Item stable IDs;
- final material art profiles.

Those remain owned by universal systems, FCC-05H–J and FCC-12/FCC-13.

The governing rule is:

> **A realm-specific physical object exists only when its material, structure, lifecycle or function is genuinely Ascendant-specific. Universal content is reused rather than renamed.**

A second binding rule is:

> **A placeable object that recovers as itself is one canonical Block plus a Block Inventory Projection, not a duplicated authored Item.**
