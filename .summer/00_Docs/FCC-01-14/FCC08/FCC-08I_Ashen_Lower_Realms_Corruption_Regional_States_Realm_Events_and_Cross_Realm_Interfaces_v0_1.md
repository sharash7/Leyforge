# 2. Canon Statement

The Ashen Lower Realms is dangerous because it is:

- hot;
- volcanic;
- ash-filled;
- industrial;
- politically fragmented;
- contract-heavy;
- capable of famine;
- capable of war;
- capable of coercive labour systems;
- home to Hunger-Pit ecology;
- home to Black Ember and Cold Fire phenomena;
- home to colossal furnace systems;
- ecologically and politically dynamic.

None of those facts makes the realm inherently Void-corrupted.

The realm therefore distinguishes three broad concepts:

1. **ordinary native conditions;**
2. **regional crises and dynamic states;**
3. **genuine external Void corruption.**

This distinction is mandatory.

---

# 3. Void Corruption Provenance Rule

A region, material, creature, structure, law system, magical system or person is classified as **Void-corrupted** only when actual Void provenance exists.

Valid provenance may include:

- a confirmed Void Fracture;
- a known Void-contaminated entity;
- Void-tainted material;
- spread from an established corrupted region;
- an authored future Void-interface event;
- another globally recognised corruption source.

“Corrupted” must not be used casually as a synonym for:

- infernal;
- dangerous;
- evil;
- hot;
- hungry;
- hostile;
- tyrannical;
- magical;
- ancient;
- unstable;
- industrial.

# 5. Corruption State-First Rule

Void corruption normally appears as a:

- state;
- overlay;
- variant;
- contamination;
- behavioural modifier;
- regional modifier;
- structure condition;
- material condition.

A new permanent Block, Item, creature or material definition is justified only where corruption causes **irreversible transformation into genuinely distinct matter or entity identity**.

This protects the registries from uncontrolled duplication.

# 6. Corruption Scope

Void corruption may affect:

- one object;
- one person;
- one creature;
- one structure;
- one dungeon;
- one route;
- one settlement district;
- one biome region;
- one Cinder-Sea zone;
- multiple linked regions.

It is not assumed to be realm-wide.

# 7. Corruption Spread

Corruption spread must use explicit pathways.

Potential pathways include:

- contaminated matter;
- corrupted creature movement;
- corrupted infrastructure;
- magical propagation;
- a persistent Void Fracture;
- cross-realm contamination;
- authored corrupted-state expansion.

Corruption does not jump arbitrarily to unrelated regions because a timer elapsed.

# 9. Corruption Restoration

A corrupted region may potentially be:

- cleansed;
- stabilised;
- quarantined;
- partially restored;
- permanently scarred;
- abandoned.

Restoration outcome depends on:

- severity;
- duration;
- affected systems;
- material transformation;
- ecological damage;
- infrastructure damage;
- player/faction action.

“Cleanse corruption” does not automatically restore every destroyed structure, extinct local population or political relationship.

---

# 10. Corruption & Contracts

Void corruption may:

- damage records;
- alter a corrupted actor's behaviour;
- interfere with enforcement infrastructure;
- produce fraudulent/corrupted systems.

It does **not** retroactively create player consent.

An accepted magical contract cannot be silently rewritten merely because a region becomes corrupted.

If contract infrastructure is compromised, the system must distinguish:

- valid accepted terms;
- forged records;
- damaged records;
- corrupted enforcement;
- actual amendment.

---

# 11. Corruption & Debt / Soul-Related Pacts

Debt may exist as:

- legal obligation;
- economic obligation;
- accepted magical contract state.

Future soul-related pact content, if supported globally, must remain:

- explicit;
- readable;
- bounded;
- compatible with universal death;
- unable to erase character identity;
- unable to turn a person into generic transferable inventory property.

Void corruption does not override these boundaries.

---

# 12. Corruption & Universal Death

Void corruption does not own the death system.

Universal Leyforge death/respawn remains authoritative.

A corrupted region may affect:

- route safety;
- recovery difficulty;
- checkpoint access;
- structure availability.

It cannot create an independent Ashen/Void death law.

# 14. Stable Ashen State

## 14.1 Identity

**Stable Ashen State** is the baseline known regional condition.

It means:

- hazards are within expected local ranges;
- routes broadly match known state;
- major infrastructure is not undergoing exceptional crisis;
- local government/ownership is not undergoing exceptional transition.

## 14.2 Stable Does Not Mean Safe

A stable region may still be:

- extremely hot;
- heavily industrial;
- politically hostile;
- legally restrictive;
- predator-rich;
- difficult to traverse.

Stable means **baseline**, not easy mode.

# 24. State Conflict Resolution

Where two state effects conflict, resolution must be explicit and deterministic.

Priority should consider:

1. physical validity;
2. authored event cause;
3. persistent pre-existing state;
4. current controlling authority/faction where relevant;
5. corruption overlay where applicable;
6. save-safe deterministic fallback.

No load-order accident should decide world truth.

---

# 25. State Count Must Remain Bounded

The system should not generate hundreds of micro-states for every minor variation.

Minor differences should use:

- parameters;
- severity;
- local data;
- biome expression;
- structure state.

A new principal state family is justified only when it represents a genuinely distinct world-system condition.

---

An **event** is an occurrence/process.

A **regional state** is the resulting condition.

Examples:

- Furnace Surge event → Furnace Surge state;
- Great Ashfall → Ashstorm state;
- March War/Invasion → Warfront state;
- Ledger Crisis → Ledger Shift;
- Hunger Bloom/Ration Crisis → Hunger Pressure;
- Chain Uprising/Liberation Crisis → Chain Crisis;
- Void Fracture → Void-Corrupted State.

The two layers should not be collapsed into one registry type.

# 54. Ashgate Save-Safety Rule

- repair;
- validated fallback arrival/exit;
- alternate Ashgate of the same family;
- supported recovery infrastructure.

The solution remains within the Ashgate family.
