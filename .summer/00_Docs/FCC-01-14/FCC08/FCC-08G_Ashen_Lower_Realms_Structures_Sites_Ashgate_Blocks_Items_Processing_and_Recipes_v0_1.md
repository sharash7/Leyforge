# 2. Canon Statement

FCC-08G turns already-locked Ashen canon into **usable physical game content** without creating unnecessary duplicate definitions.

Its core rules are:

1. **One physical thing should have one canonical identity.**
2. **Placeable Blocks are not duplicated as Items merely because inventory representation exists.**
3. **Processed Items exist only when transformation creates a genuinely different form.**
4. **A new material does not require a new workstation by default.**
5. **Universal processing systems remain authoritative wherever physically appropriate.**
6. **Specialist Ashen stations exist only for genuinely distinctive processes.**
7. **Recipe progression follows real capability and provenance rather than floor-key gating.**
8. **Ashgate is one portal family with staged capability, not multiple Ashen portals.**
9. **Physical matter retains cross-realm behaviour unless genuine physical/magical incompatibility exists.**
10. **Exact numbers are deferred until the final global registry/recipe pass.**

# 4. Block / Item Single-Definition Rule

The universal Leyforge rule remains authoritative:

> If something is fundamentally a placeable Block and remains/recoverably returns as that same Block when broken, it remains one canonical Block definition with inventory representation.

Therefore FCC-08G must not create both:

- `Basalt Block`
- `Basalt Block Item`

as unrelated canonical content.

The same applies to:

- Ash Brick;
- Hellglass Block;
- Hellglass Pane;
- natural crystal clusters where the mined object remains that same cluster;
- structure Blocks that retain their identity when recovered.

Separate Items are appropriate when the matter is transformed into forms such as:

- ore;
- ingot;
- plate;
- rod;
- wire;
- fittings;
- powder;
- ash;
- salt;
- crystal shard;
- treated hide;
- pearl;
- fuel unit;
- seal component;
- machinery component;
- gas canister.
