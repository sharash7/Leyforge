# 6. Global Canon Principles Certified by FCC-01

The Overworld package consistently preserves the following rules.

## 6.1 Single-Definition Physical Identity

Do not create duplicate Items/materials/structures merely to represent:

- condition;
- location;
- owner;
- corruption;
- construction phase;
- occupation;
- broken state

unless identity truly changes.

For Blocks:

> If the placed block remains the same object when broken, inventory uses the same Block definition/projection rather than a duplicate Item definition.

Final registry implementation is FCC-13-owned.

## 6.2 State Before Duplicate Identity

Prefer state/variant for:

- corruption;
- blight;
- damage;
- wet/dry;
- charged/depleted;
- occupied/abandoned;
- cultivated/naturalised;
- repaired/restored.

Create a distinct definition only when the thing truly becomes a new identity.

## 6.3 Provenance Before Theme

Do not infer realm origin from:

- colour;
- biome;
- darkness;
- roots;
- dreams;
- graves;
- height;
- depth;
- fire;
- gravity;
- religion.

A realm claim requires a real source/pathway/history.

## 6.4 Capability Before Realm Tier

A capable tool, material, machine, spell or method can work outside its origin realm when it genuinely satisfies the requirement and survives the environment.

There is no hidden universal realm gear ladder.

## 6.5 Physical Conservation

Goods, mana, cargo, creatures, structures and resources do not duplicate or vanish because of:

- LOD;
- UI;
- streaming;
- trade summary;
- automation animation;
- portal presentation.

Physical transfer must have real source/destination transaction state.

## 6.6 Personhood Before Convenience

Hostility, undeath, construct body, collective embodiment, legal oppression or dungeon location do not remove personhood.

## 6.7 Persistent Consequence

Dungeons, bosses, settlements, wars, ecological events, roads, structures and realm-contact crises create persistent aftermath rather than generic reset.

# 12. FCC-12 Handoff — Universal Materials, Processing & Derived Forms

FCC-01 has completed its content-side material handoff.

| FCC-12 Handoff Area | Required Reconciliation |
| --- | --- |
| Shared identity / equivalence | Resolve shared/common identities such as Basalt and ordinary physical matter that exists across realms without duplicating the material. |
| Cross-realm physical persistence | Bind the rule that ordinary physical matter generally keeps its physical properties after export while specialist realm-dependent magical behaviour may weaken, go dormant or require stabilisation. |
| Thunder Glass vs Stormglass | Keep native Overworld Thunder Glass distinct from Ascendant Stormglass. |
| Silver vs Soul Silver | Keep ordinary Silver distinct from Ancestral Soul Silver. |
| Frost Pearl vs Pressure Pearl | Keep Overworld Frost Pearl distinct from Impossible Deep Pressure Pearl. |
| Greatheart / Living Heartwood boundary | Keep Verdant-specific Greatheart/Living Heartwood distinct from native Overworld timber foundations. |
| Fae Grass / special vegetation relationship | Resolve any shared/special vegetation equivalence or provenance treatment through the universal material/organism ontology rather than duplicated realm rows. |
| Glass / crystal / fibre / wood taxonomy | Resolve universal family relationships, grades, processed forms and when provenance is state versus a distinct material. |
| Derived forms | Bind ingots, plates, rods, wire, dust, shards, fibres, boards/planks, glass forms, salts, powders, oils and other derived forms to source material identities. |
| Processing deduplication | Reuse universal processing families/stations unless a realm process is genuinely distinctive. |
| Provider roles / substitution | Resolve material/provider equivalence for capability roles, including portal structural/conductive/vessel roles, without inventing filler materials. |
| Export stabilisation | Define when exported materials/organisms retain specialist effects, require support or lose only realm-dependent behaviours. |
| Transformation vs state | Confirm reversible/corrupted/treated conditions as state/variant unless true identity change warrants a separate material. |
| Naming normalisation | Resolve universal material naming and inherited/provenance display rules without overwriting realm-specific names that are genuinely distinct. |

## 12.1 FCC-12 Must Not

FCC-12 must not:

- delete a locked Overworld material because another realm contains a similar material;
- convert provenance variants into duplicates without need;
- silently merge Thunder Glass with Stormglass;
- merge ordinary Silver with Soul Silver;
- merge Frost Pearl with Pressure Pearl;
- reintroduce old linear-tier logic;
- invent portal filler materials;
- rewrite realm-specific material identity simply to simplify implementation.

FCC-12 is the **ontology/reconciliation owner**, not a new content questionnaire.
