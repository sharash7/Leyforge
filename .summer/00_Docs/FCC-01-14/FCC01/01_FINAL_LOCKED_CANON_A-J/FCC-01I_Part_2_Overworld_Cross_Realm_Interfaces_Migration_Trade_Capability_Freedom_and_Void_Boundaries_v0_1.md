# 1. Purpose

FCC-01I Part 2 defines what it means for the Overworld to coexist with six current major realms without collapsing them into one world.

It owns content-level canon for:

- realm influence and provenance;
- Overworld-side cultivation and imported ecology;
- migration and diaspora;
- cross-realm trade;
- religious/historical/research contact;
- bounded dream/spirit/resonance information interfaces;
- cross-realm material behaviour;
- realm-event consequences;
- portal/discovery knowledge interface;
- pre-access foreign provenance;
- capability freedom;
- cross-realm event-transfer contract;
- quarantine/invasive/contamination boundaries;
- final Void provenance distinction.

The governing principle is:

> **Knowledge can cross without matter. Matter crosses only through legitimate physical transfer. People retain personhood. Materials retain provenance. Realm-specific physics/law does not automatically spread with exported objects. Similarity is not provenance. Portal clues are not portal bypasses.**

# 43. Capability Freedom

The locked rule is:

> **Capability matters; realm origin does not.**

| Rule | Canonical Meaning |
| --- | --- |
| Symmetric capability freedom | Overworld providers work in realms and realm-developed providers work in Overworld when they truly satisfy the required capability. |
| No wrong-dimension disabling | A tool/machine/material does not lose real function solely because it came from another realm. |
| Environmental truth remains | Heat, pressure, atmosphere, corrosion, gravity, mana, sacred-law or contract-context requirements remain real. |
| Substitution by compatibility | Materials/providers may substitute where physical/magical capability actually matches; FCC-12/FCC-13 bind exact equivalence. |
| No universal realm tier ladder | Verdant/Veil/Dream/Ascendant/Deep/Ashen are not a simple ascending gear-rarity ladder. |
| Knowledge portability | Engineering/magical knowledge may transfer without moving the original physical system; implementation still needs real local materials/infrastructure. |
| Sequence breaking allowed | If the player legitimately has knowledge, capability, materials, site access and activation conditions, the game recognises the valid solution. |

This is symmetric.

# 44. Examples of Capability Freedom

A valid Overworld provider can solve realm problems.

Examples:

- sufficiently capable Overworld drill → Ashen excavation;
- pressure-rated Overworld vessel → compatible Deep engineering;
- Overworld lightning protection → Ascendant storm infrastructure;
- controlled greenhouse → compatible realm crop.

Likewise:

- Deep seismic sensor → Overworld geology;
- Ascendant weather engineering → Overworld storm systems;
- Ashen metallurgy → Overworld industry;
- Verdant restoration practice → Overworld ecology.

The game asks whether the capability is **actually sufficient**, not whether the Item's origin matches the destination.

# 47. Cross-Realm Event Contract

For an event in one realm to create an Overworld effect, the interface must identify:

| Contract Element | Requirement |
| --- | --- |
| Originating event | Which realm/system event actually occurred? |
| Transfer vector | Portal, cargo, traveller, information, diplomacy, contamination, trade route or other explicit interface. |

| Scope and persistence | What bounded consequence occurs and how long/history/persistence is recorded? |

This keeps cross-realm consequences bounded and explainable.

# Appendix B — Capability-Freedom Quick Test

A provider is valid when:

1. it supplies the required **actual capability**;
2. it can survive/operate in the environment;
3. any declared magical/legal/system context is satisfied;
4. the user has legitimate access/knowledge/permission where required.

Its realm of origin is not an automatic pass or fail.

# Appendix C — Void Quick Test

Ask:

1. **What is the alleged Void source?**
2. **What pathway transferred the corruption?**
3. **What underlying thing is corrupted?**
4. **What evidence distinguishes it from native blight/anomaly/nightmare/spirit/deep/infernal phenomena?**

If those questions cannot be answered, the content must not silently be labelled Void.
