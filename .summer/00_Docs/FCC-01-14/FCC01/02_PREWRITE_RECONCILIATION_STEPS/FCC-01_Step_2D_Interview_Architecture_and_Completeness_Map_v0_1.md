# 1. Purpose

This document is the final hard-reference roadmap for the FCC-01 Overworld interview. It does **not** answer the Overworld content questions.

It defines the final interview order, ownership boundaries, source feeds, realm-interface feeds, question-number planning bands, section completion gates, A–J document mapping, cross-section dependencies and the final theoretical-completeness gate.

The goal is to make FCC-01 large because the Overworld itself is content-rich, **not** because it absorbs universal systems, exact portal recipes, migration work or final registry/art tasks.

---

# 2. Authority and Source-Use Rule

1. Locked universal/global system documents remain authoritative inside their declared ownership.
2. Completed realm FCC A–J sets remain authoritative for realm-local canon and explicit Overworld requirements.
3. Set 24 is the primary pre-FCC Overworld candidate/content inventory.
4. Foundation 00–20 and Sets 20, 25–30 supply existing foundations and constraints.
5. Sets 21–23 constrain later Forge/presentation/asset handoff but do not decide content identity.
6. Prototype/runtime registries and POC content are migration evidence, not final canon.
7. Steps 2A–2C control reconciliation scope and routing.

When an older source conflicts with a later locked FCC decision, the later FCC decision controls; the older source survives only as migration/provenance evidence where useful.

# 4. Interview Operating Rules

## 4.1 Format and cadence

- Default to multiple-choice questions with a clear recommended answer.
- Preserve user overrides/additions and distinguish old source candidates from new FCC proposals.
- Default batch: **20–30 questions**.
- Narrow reconciliation batches: **15–22**.
- Roster-heavy batches: **25–35**.
- Lock a section only when its content gate passes; do not use filler questions.

## 4.2 Planning envelope

Step 2D reserves a **provisional Q1–Q1400 envelope**. This is a routing ceiling, not a quota.

Section IDs **S01–S36** are the stable roadmap references. If a section closes early or expands, numbering continues normally and the reviewed roadmap can be updated later.

## 4.3 Excluded implementation detail

Unless a genuine content decision depends on them, FCC-01 should not ask for exact stable IDs, exact recipe quantities, processing seconds, throughput, DPS/armour numbers, crop-day values, spawn percentages, event probabilities, save schemas, shader values, RGB values or LOD distances.
