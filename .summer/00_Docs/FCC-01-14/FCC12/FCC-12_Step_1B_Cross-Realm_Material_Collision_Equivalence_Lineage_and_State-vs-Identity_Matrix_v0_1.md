# 1. Purpose

Step 1A established **what material families exist**.

Step 1B establishes **how those families relate to one another**.

For every meaningful collision, Step 1B asks:

- Is this the **same material** appearing in more than one realm?
- Is it a **distinct material** that merely shares a broad material class?
- Is it a **state/facies/condition** of another material?
- Is it a **processed form**?
- Is it an **irreversible transformed material**?
- Is it an **alloy/formulation**?
- Is it a **manufactured component** rather than a material?
- Is the different name only **provenance**, **culture**, **legacy alias** or **role terminology**?
- Is the old term **rejected**, **retired**, or **deferred**?

The purpose is to stop FCC-13 from receiving a flat list of hundreds of names with no relationship graph.

# 2. Relationship Classes Used in This Matrix

| Relationship Class | Meaning |
| --- | --- |
| **SHARED MATERIAL** | One canonical physical material identity exists across more than one world/realm; provenance/location may still differ. |
| **DISTINCT SIBLING MATERIAL** | Materials share a broad superclass but remain separately canonical substances. |
| **STATE / FACIES / CONDITION** | Underlying material identity remains the same; changed properties are carried as state. |
| **PROCESSED FORM** | Input matter is processed into a meaningful product while retaining a clear parent lineage. |
| **TRANSFORMED MATERIAL** | Processing/environment creates sufficiently different matter to justify a distinct derived material identity. |
| **ALLOY / FORMULATION** | Material is manufactured by combining/refining compatible inputs rather than mined as a native ore. |
| **MANUFACTURED COMPONENT** | Crafted system part; not a natural raw-material family. |
| **PROVENANCE / SOURCE VARIANT** | Same material identity but source/history differs meaningfully. |
| **CULTURAL / ROLE TERM** | Name describes use, culture, trade, function or interpretation rather than independent material identity. |
| **LEGACY ALIAS / MIGRATION** | Older implementation/source term requires compatibility routing but is not current independent canon. |
| **REJECTED GENERIC TERM** | Term must not become a universal filler resource/material. |
| **DEFERRED FUTURE CONTENT** | Current material ontology cannot activate the concept as normal present content. |
| **OPEN FCC-12 DECISION** | Source canon deliberately hands the final global relationship to FCC-12. |

# 4. Universal Principle — Superclass Does Not Mean Merge

FCC-12 requires broad universal material superclasses such as:

- stone;
- soil/earth;
- sand/sediment;
- clay/ceramic feedstock;
- glass;
- crystal;
- metal;
- alloy;
- wood/timber;
- fibre/thread/textile;
- resin/sap/wax/oil;
- salt/mineral reagent;
- biomineral/pearl;
- biological hard material;
- fluid;
- gas/aerosol;
- energetic resource;
- particulate/powder;
- manufactured component.

However:

> **Two materials belonging to one superclass does not make them one material.**

Examples already locked:

- ordinary Silver and Soul Silver can both be metals while remaining distinct;
- Thunder Glass and Stormglass can both be glass/crystal materials while remaining distinct;
- Frost Pearl and Pressure Pearl can both be pearl/biomineral materials while remaining distinct.

This distinction is foundational.

# 32. Step 1B Findings

## Finding A — Most Name Collisions Are Not True Identity Collisions

The current FCC corpus already distinguishes:

- material;
- state;
- processed product;
- component;
- provenance;
- cultural name.

Many old duplicates disappear once the relationship type is explicit.

---

## Finding B — Universal Superclasses Are Essential

FCC-12 needs a shared taxonomy so systems can ask:

- `is stone?`
- `is timber?`
- `is conductive metal?`
- `is fibre?`
- `is optical glass?`
- `is salt/mineral reagent?`
- `is biomineral?`

without requiring identical material identity.

This is what enables capability substitution without collapsing lore/provenance.

---

## Finding C — Shared Matter Should Be the Exception Proven by Physical Identity, Not by Similar Name

Basalt is the clearest already-locked shared example.

By contrast:

- Iron / Abyssal Iron / Skyiron / Ember Iron;
- ordinary Glass / Lucid Glass / Stormglass / Ventglass / Hellglass;
- ordinary Silver / Soul Silver;
- ordinary pearls / realm pearls

must not be merged merely because their nouns resemble one another.

---

## Finding D — The Old POC Registry Is Structurally Flatter Than the FCC Canon

The POC registry tends to represent:

> one display name → one Block/Item row.

The FCC model instead requires:

> material identity → lineage → state → allowed form → Block/Item projection → provenance.

FCC-13 therefore cannot simply clean names in the old registry.

It must migrate the registry onto the FCC-12 relationship graph.
