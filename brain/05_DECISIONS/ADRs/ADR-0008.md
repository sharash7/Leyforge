# ADR-0008 — Development-only external harness boundary for PRD-07 proof execution

## Status and Authority

**ACCEPTED on 2026-09-06 by Ash, project owner.** Acceptance governs the development-only PRD-07 proof-harness boundary described here. It does not accept ADR-0001 through ADR-0007, activate a production dependency, authorize R8 gameplay, close CONFLICT-0002 or turn prototype evidence into production certification.

## Context / Problem

PRD-07 requires reusable proof infrastructure before W0 execution. The clean rebuild contains documents, Brain records and Python verification tools; at proposal time it had no V1 Godot runtime, `project.godot`, active Godot/Zylann dependencies or exported artifacts. A boundary is needed that can verify its own contracts and later control real external artifacts without placing prototype code inside production modules.

## Authoritative Constraints

PRD-07 sections 121–124 allow a logical harness implemented by scripts, CI, engine tooling or external controllers; sections 164–165 require strict artifact/identity controls and no run allocation before READY. ENG-GOV-02 separates tooling/fixtures from runtime. ENG-GOV-05 requires deterministic isolated contract/integration verification. ENG-GOV-07 requires structured reproducible diagnostics. ENG-GOV-09 separates semantic identity from projections/runtime identity. ENG-GOV-10 requires real evidence for performance claims. ENG-GOV-11 distinguishes prototype evidence from production authority. R8 remains closed and the POC remains evidence only.

## Decision

Use `tools/proof_harness/` as the accepted development-only external harness boundary for PRD-07. It provides public contracts for semantic/world/session/frame identity; runtime binding and disposable projections/read models; build/dependency/artifact manifests; external process and client/headless smoke control; read-only dependency lint; structured diagnostics/evidence-pack validation; and PRD-07 state/readiness control.

The harness owns no production state and imports no runtime or POC implementation. Runtime/provider proof adapters must use explicit boundaries under a governed R7 Task Contract. A smoke result is evidence-eligible only for a real hash-verified export with exact build identity during an actual governed run. Synthetic fixtures may test the controller but remain permanently ineligible for PRD-07 evidence.

## Alternatives Considered

- Wait for the V1 runtime: delays testing of critical identity, manifest and evidence controls.
- Create a normal gameplay project solely for W0: crosses the closed R8 boundary.
- Use one-off scripts per proof: duplicates cross-wave semantics and weakens comparison.

## Positive Consequences

Bootstrap contracts can be tested before production architecture is selected, real proof artifacts can be controlled through one evidence boundary, and synthetic tests cannot masquerade as proof evidence.

## Negative Consequences

A separate runtime adapter is required for engine/provider proofs, and engine instrumentation must remain aligned with both this harness contract and the canonical proof specifications.

## Risks / Assumptions

Python is assumed available in CI. Harness certification validates harness semantics, not Godot/provider behavior. Runtime proof candidates remain provisional and cannot silently settle the production Godot, Voxel Tools edition, fork or persistence decisions.

## Rationale / Evidence

Certified state commit `c25daedd33dc33ece3f70ab6867f6477a40c4ea1` passes the stable full gate, 28 W0 tests, architecture-lint fixtures, both Doctors, generated-state/link checks and 2,993 clean-rebuild boundary checks in a fresh LF checkout. [[EVID-0005]] and [[AUDIT-0005]] certify the implementation behavior and its limits. The owner acceptance recorded here supplies the acceptance authority that those records deliberately did not claim.

## Reconsideration Triggers

- A governed production V1 runtime/module manifest requires a materially different boundary.
- Real W0 execution shows the external contract cannot capture required evidence.
- Supported implementation language or CI changes.
- A later accepted ADR supersedes this development-only boundary.

## Affected Systems / Documents

`tools/proof_harness/`, `tools/tests/`, [[TASK-20260906-004]], [[WORK-20260906-004]], [[TASK-20260906-005]], [[WORK-20260906-005]], and PRD-07 run/evidence records created only after valid execution gates.

## Verification

Brain and governance validators, generated decision indexes, stable repository verification and the clean-rebuild boundary must continue to pass. Every real smoke/proof record must retain exact dependency, build and artifact identity.
