# ADR-0008 — Development-only external harness boundary for PRD-07 proof execution

## Status and Authority

**PROPOSED.** This preserves the Class C decision and rationale. It does not claim owner review, acceptance, production authority or R8 permission.

## Context / Problem

PRD-07 requires reusable proof infrastructure before W0 execution. The clean rebuild contains documents, Brain records and Python verification tools; it has no V1 Godot runtime, `project.godot`, active Godot/Zylann dependencies or exported artifacts. A boundary is needed that can verify its own contracts and later control real external artifacts without placing prototype code inside production modules.

## Authoritative Constraints

PRD-07 sections 121–124 allow a logical harness implemented by scripts, CI, engine tooling or external controllers; sections 164–165 require strict artifact/identity controls and no run allocation before READY. ENG-GOV-02 separates tooling/fixtures from runtime. ENG-GOV-05 requires deterministic isolated contract/integration verification. ENG-GOV-07 requires structured reproducible diagnostics. ENG-GOV-09 separates semantic identity from projections/runtime identity. ENG-GOV-10 requires real evidence for performance claims. ENG-GOV-11 permits proposal but not invented acceptance. R8 remains closed and the POC remains evidence only.

## Proposed Decision

Create `tools/proof_harness/` as a development-only Python standard-library package with public contracts for semantic/world/session/frame identity; runtime binding and disposable projections/read models; build/dependency/artifact manifests; external process and client/headless smoke control; read-only dependency lint; structured diagnostics/evidence-pack validation; and PRD-07 state/readiness control.

The harness owns no production state and imports no runtime or POC implementation. Later runtime/provider adapters must use explicit boundaries after their authorities exist. A smoke result is evidence-eligible only for a real hash-verified export with exact build identity during an actual governed run. Synthetic fixtures may test the controller but remain permanently ineligible for PRD-07 evidence.

## Alternatives Considered

- Wait for the V1 runtime: delays testing of critical identity, manifest and evidence controls.
- Create a Godot project solely for W0: crosses the closed R8/dependency boundary.
- Use one-off scripts per proof: duplicates cross-wave semantics and weakens comparison.

## Consequences

Bootstrap contracts can be tested without dependencies, real artifacts remain controllable later, and synthetic tests cannot masquerade as proof evidence. A future runtime adapter will be required, and engine instrumentation must remain aligned with these contracts.

## Risks / Assumptions

Python is assumed available in CI. The bootstrap validates harness semantics, not Godot/provider behavior. Scope is limited to section-164 priorities to avoid premature abstraction.

## Evidence and Verification

Certified state commit `c25daedd33dc33ece3f70ab6867f6477a40c4ea1` passes the stable full gate, 28 W0 tests, architecture-lint fixtures, both Doctors, generated-state/link checks and 2,993 clean-rebuild boundary checks. [[EVID-0005]] and [[AUDIT-0005]] certify the implementation behavior and its limits. Certification of the bootstrap does not accept this proposal.

## Reconsideration Triggers

- An accepted V1 runtime/module manifest or governed Godot/Zylann export targets exist.
- Real W0 execution shows the external contract cannot capture required evidence.
- Supported implementation language or CI changes.
- Owner/delegated architecture review accepts, changes or rejects this proposal.

## Affected Systems / Documents

`tools/proof_harness/`, `tools/tests/`, `tools/verify.py`, [[TASK-20260906-004]], [[WORK-20260906-004]], and future PRD-07 run/evidence records after separate execution gates.
